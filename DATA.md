# Data

tagvault uses **no external datasets**. Every signal, message and capture is synthetic and is
generated by committed code from fixed seeds, so every number is reproducible.

| data | where it comes from | committed? | license |
|---|---|---|---|
| Process signals (tank level with hysteresis pump, temperature and flow first-order loops with setpoint steps and trips, OU pressure) | `src/sim/signals.rs`, SplitMix64 seeds | no (generated on demand) | MIT (this repo) |
| Benchmark split | tuning seeds 1–8, held-out seeds 101–116 per class, 21 600 samples (6 h at 1 s) each | no | MIT |
| Plant scenario captures (`*.tvcap`) | `tagvault simulate` (`src/sim/capture.rs`): 2 edge nodes × (Tank01, Reactor01), lossy link (DDATA loss p = 0.0003, swaps p = 0.001), one node restart | no (written to `out/` by `make demo`) | MIT |
| Sparkplug decode test payloads | hand-encoded with the independent protobuf writer in `tests/common/mod.rs`; metric names, types and values are modelled on the example messages in the Eclipse Sparkplug 3.0 specification | yes (in test code) | MIT (the payload bytes); the Sparkplug specification itself is published by the Eclipse Foundation's Sparkplug Working Group and is not redistributed here |
| Demo policy | `fixtures/policy.json` (hand-written deviations per signal type) | yes | MIT |

Optional only: `make integration` pulls the `eclipse-mosquitto:2.0.20` Docker image
(Eclipse Public License 2.0 / Eclipse Distribution License 1.0) to run a real MQTT broker. It is
not needed for `make check` or `make demo`.

## Disclosure

All data is simulated. The signal models are plausible shapes (hysteresis, first-order lag,
setpoint steps, trips, Gaussian measurement noise) and are not calibrated against any real
plant. Compression ratios on real process data depend heavily on noise levels and on the
deviations an engineer chooses. Treat the benchmark as a comparison between methods on the same
signals, not as a prediction for your plant.
